# Пространство · альбомы и оценки

Тёмный закрытый сайт для двоих: общая коллекция альбомов, оценки по трекам,
профили артистов и рейтинг. Матовый монохром, тёплый белый, деликатная
пыльная лаванда, плавные анимации. Полностью адаптирован под мобильные.

## Возможности

- Вход по профилю → пароль (два участника, один — админ).
- Карточки альбомов (обложка, год, тип релиза, средний балл).
- Добавление альбома: подсказки артистов, обложка файлом/ссылкой, защита от дублей.
- Страница альбома: оценка **каждого трека** слайдером/числом (до 2 знаков),
  средний балл альбома в реальном времени.
- Подтверждение («фиксация») своей оценки на треке; итог альбома считается
  подтверждённым, только когда оба участника подтвердили все оценки.
- Фиты: в названии трека `ft.` / `feat.` / `&` открывает поле «при участии»;
  имя фитующего артиста становится ссылкой с синим неоном.
- Профиль артиста: средний балл крупно, личные альбомы и раздел «при участии».
- Рейтинг артистов: сортировка по среднему баллу, топ-3 с золотой/серебряной/
  бронзовой подсветкой, аватар — обложка лучшего альбома.
- «Мой профиль»: аватар (применяется везде) и смена никнейма.
- Drag & drop треков (на десктопе), фиксация названий и количества (админ),
  целостность/тип релиза — финальный необратимый выбор, удаление альбома с
  анимацией «осыпания» обложки.
- Живая синхронизация между участниками (Supabase Realtime).

## Два режима

| Режим | Когда | Данные |
|-------|-------|--------|
| **Демо** | `supabaseUrl` пуст | localStorage — только на этом устройстве |
| **Облако** | указаны ключи Supabase | общая база для двоих + живая синхронизация |

Демо-вход: `killmiplag@demo.local` / `demo` или `elevator@demo.local` / `demo`.

## Файлы

| Файл | Что это |
|------|---------|
| `index.html` | Разметка (вход, главная, альбом, артист, рейтинг, профиль, добавление) |
| `styles.css` | Вся стилизация, анимации, адаптив |
| `app.ts`     | Логика (TypeScript, исходник) |
| `app.js`     | Собранный бандл (подключается в HTML) |
| `config.js`  | **Настройки: ключи Supabase и список участников** |
| `schema.sql` | SQL-схема **для новой базы** |
| `migrate.sql`| Идемпотентное обновление **существующей базы** до актуальной схемы |
| `package.json`, `tsconfig.json`, `package-lock.json` | Сборка |
| `server.py`  | Локальный сервер без кэша |
| `covers/`    | Обложки для демо-данных |

## Запуск локально

```bash
cd site
python3 server.py      # → http://localhost:8080
```

## Подключение Supabase

1. **Создайте проект** на https://supabase.com (бесплатно).
2. **Project Settings → API** — скопируйте **Project URL** и **anon key**.
3. Вставьте их в `config.js` (поля `supabaseUrl`, `supabaseAnonKey`).
4. Там же замените почты участников на настоящие:
   ```js
   allowedUsers: [
     { email: "ваша@почта.домен", username: "киллмиплаг", initials: "к", admin: false },
     { email: "почта@второго.домен", username: "Elevator", initials: "E", admin: true },
   ]
   ```
5. **SQL Editor → New query**:
   - новая база — вставьте `schema.sql` и нажмите Run;
   - база уже создавалась раньше — вставьте `migrate.sql` (можно повторять).
6. **(Рекомендуется)** Authentication → Sign In / Providers → Email →
   отключите «Confirm email», чтобы регистрация входила сразу.
7. Откройте сайт → «создать» → зарегистрируйте оба аккаунта
   (почта должна совпадать с `allowedUsers`).

## Структура данных (облако)

- `profiles` — участники (id из auth.users, username, initials, avatar_url)
- `albums` — артист, название, год, обложка, tracks_locked, cohesion, album_type
- `tracks` — треки альбома (title, position, locked, feat_artist)
- `ratings` — оценка участника на треке (score 0–10, confirmed)
- `storage.buckets.covers` — обложки и аватары (публичное чтение)

Безопасность на RLS: читают/пишут только вошедшие; свои оценки, ник и аватар
меняет только их владелец; пароли хранит Supabase Auth.
