# Пространство · альбомы и оценки

Тёмный закрытый сайт для двоих: общая коллекция альбомов и синглов, оценки по
трекам и релизам, профили артистов и рейтинги. Матовый монохром, тёплый белый, деликатная
пыльная лаванда, плавные анимации. Полностью адаптирован под мобильные.

## Возможности

- Вход по профилю → пароль (два участника, один — админ).
- Карточки альбомов (обложка, год, тип релиза, средний балл).
- Добавление альбома: подсказки артистов, обложка файлом/ссылкой, защита от дублей.
- **Поиск обложек онлайн**: при добавлении альбома/сингла и при изменении обложки
  варианты автоматически ищутся по **Deezer**, **Genius** и **iTunes**
  (выбор — с анимацией и штатным сохранением; ошибки — с деталями и кнопкой
  «скопировать отчёт»); новые платформы добавляются одним объектом-адаптером.
- Страница альбома: добавление или замена обложки **после создания** (файл/ссылка,
  предпросмотр, сохранение или отмена); оценка **каждого трека** слайдером/числом
  (до 2 знаков), средний балл альбома в реальном времени.
- Замена обложки — с эффектом: новая обложка «проявляется» с лёгким увеличением,
  по ней проходит блик и вспыхивает лавандовый контур (на страницах альбома и сингла;
  только замена, не первое добавление; при уменьшении движения отключается).
- Подтверждение («фиксация») своей оценки на треке; итог альбома считается
  подтверждённым, только когда оба участника подтвердили все оценки.
- Фиты: в названии трека `ft.` / `feat.` / `&` открывает поле «при участии»;
  имя фитующего артиста становится ссылкой с синим неоном.
- Фит в названии сингла: если название сингла записано как `Название & Гость`
  или `Название (feat. Гость)`, в списках и на странице сингла показывается
  чистое название, а блок артиста — полный состав исполнителей («Артист & Гость»
  или «Артист (feat. Гость)»); каждое имя — ссылка на профиль. `ft.` при показе
  автоматически превращается в `feat.` и берётся в скобки. Запись в базу не меняется.
  Распознаются `feat.`/`ft.` и без точки.
- Фит на экране добавления сингла — прямо в поле артиста: `Артист & Гость` или
  `Артист feat. Гость`. Основным исполнителем становится первый, гость записывается
  в название сингла и виден в блоке артиста. Поле называется «Артист или совместка»
  и несёт подсказку о синтаксисе; пока печатаете гостя, подсказка подтверждает
  распознанного гостя («фит: Гость»).
- Метка «сингл» на треке с фитом: гость выносится из названия трека в блок
  артиста сингла («Артист (feat. Гость)»), название трека и сингла остаётся чистым.
- Профиль артиста: средний балл крупно, личные альбомы, **синглы** и раздел
  «при участии». В «синглах» лежат все синглы артиста — и сольные, и фиты/совместки
  («Название & Гость»): гость видит релиз там же, а не в «при участии» (этот раздел
  оставлен за альбомами, где артист участвует на фите). В карточке сингла вместо
  «0 треков» — количество оценок релиза; пока оценок нет, подписи справа нет вовсе.
- Синглы: переключатель **«альбомы | синглы»** на главной, отдельная страница
  сингла (одна оценка на релиз целиком), рейтинг синглов (только релизы, подтверждённые
  всеми участниками) и экран добавления сингла — с полем привязки к альбому.
- Оценка трека-сингла и самого сингла — **одна и та же**: подтвердили балл на альбоме —
  сингл получил ту же оценку и то же подтверждение (и попал в рейтинг синглов, если
  подтвердили оба участника); поставили балл на странице сингла — он виден и зафиксирован
  на его треке в альбоме и учтён в среднем альбома. Уже выставленные оценки при первом
  открытии сводятся автоматически.
- Метки синглов на треках: на странице альбома трек можно отметить как сингл —
  появляется бейдж и автоматически создаётся карточка сингла (название, год и
  обложка берутся у альбома). Привязанный сингл сам становится треком альбома,
  а сингл от другого артиста — совместкой «Название & Артист» со ссылкой на профиль.
- Рейтинг артистов: сортировка по среднему баллу, топ-3 с золотой/серебряной/
  бронзовой подсветкой; синглы входят в тот же средний балл, учитываются только
  подтверждённые оценки. Аватар — обложка **лучшей работы**, а не только лучшего
  альбома: сначала свои альбомы и синглы, если их нет — альбомы, где артист на фите,
  и в последнюю очередь синглы с его участием. Внутри группы берётся работа с
  наибольшим баллом, а если у неё нет своей картинки — следующая по баллу работа
  с настоящей обложкой, поэтому артист с одним синглом не остаётся с пустой
  картинкой (крайний случай — плитка с первой буквой имени).
- Меню **«рейтинги»** в шапке главной: **альбомы** / артисты / синглы / **все треки** —
  у каждого пункта иконка и счётчик («12», «7», «34»). На телефоне (≤ 700px)
  шапка — колонка и кнопка стоит у левого края, поэтому список раскрывается
  **вправо**, целиком помещаясь на экране.
- **Рейтинг альбомов** — строгий принцип, как у синглов и треков: в чарт попадает
  только альбом, где **каждый трек подтверждён всеми участниками** (как бейдж
  «подтверждён» на странице альбома); балл — среднее по трекам. Топ-3 — с подсветкой,
  остальные альбомы — внизу с честной подписью («оценок пока нет» /
  «ждём подтверждения всех оценок»). Клик по строке открывает страницу альбома.
- **Рейтинг треков** — общий чарт треков альбомов и синглов: обложка, место,
  название, артист. У альбомного трека в подписи — номер в альбоме и альбом
  («№2 · из альбома «…»»), у сингла — только артист, без номера и альбома.
  Фит-гость показывается рядом с артистом («Артист ft. Гость»). Топ-3 — с
  подсветкой; в топ попадают только треки, подтверждённые всеми участниками,
  остальные — внизу с честной подписью. Клик по треку открывает его альбом,
  по синглу — страницу сингла. Трек, отмеченный синглом, не дублируется:
  он представлен своей карточкой сингла.
- **Оценка треков на телефоне** (тач-экраны, `hover: none` + `pointer: coarse`):
  ползунок не ловит случайные касания — он «вооружается» только после тапа по строке:
  строка подсвечивается (лавандовая рамка, свечение, тонировка) — это подтверждение,
  что трек активен и готов к редактированию. Повторный тап по строке, тап вне списка
  треков или Escape снимают выделение. Числовое поле и кнопка подтверждения
  доступны сразу, без активации. Название трека, помеченного синглом, сохраняет
  прежнее поведение (модалка перехода на страницу сингла). На десктопе поведение
  не меняется.
- **Карточки релизов на телефоне** (≤ 520px — две в ряд): карточка собрана как
  колонка, обложка фиксированной высоты, а блок оценки всегда прижат к нижнему краю —
  поэтому балл у соседей по ряду стоит на одной линии и не «скачет» вверх-вниз,
  даже если у одной карточки есть строка «к альбому …» и подпись «1 без
  подтверждения», а у другой нет. Счётчик справа («12 треков», «2 оценки») —
  своим мелким шрифтом и строго в одну строку: раньше он наследовал 16px и часть
  подписей переносилась, а часть нет. Подпись про неподтверждённые оценки может
  занять вторую строку — на положение балла это не влияет.
- «Мой профиль»: аватар (применяется везде) и смена никнейма.
- **Тексты песен с Genius**: у каждого трека альбома — значок Genius (серый с
  тёмным личиком; активный — фирменный жёлтый): клик раскрывает под списком
  треков секцию с текстом песни (антиква-читалка). На странице сингла —
  «пластинка»: диск вращается, пока идёт поиск, найденный текст печатается
  посимвольно. Поиск запускается сразу при входе на сингл и по клику на
  значок трека. Найденная песня запоминается в базе (уверенное совпадение —
  автоматически; ручная замена — только админ) и видна обоим участникам.
- Подсказки в текстовых полях (артист, альбомы сингла, фит, привязки) появляются
  с плавной анимацией выезда от поля.
- Плавная прокрутка экранов добавления и рейтингов даже на слабых устройствах:
  содержимое формы кэшируется отдельным композитным слоем, строки длинных
  рейтингов вне экрана не рендерятся (content-visibility), а «дыхание»
  декоративного фона на время прокрутки приостанавливается и продолжается
  с той же фазы после остановки.
- Drag & drop треков (на десктопе), фиксация названий и количества (админ),
  целостность/тип релиза — финальный необратимый выбор, удаление альбома с
  анимацией «осыпания» обложки. Фиксация **количества** треков запрещает только
  добавлять, удалять и менять порядок: названия треков можно править и при ней
  (запрещает правку лишь фиксация **названия** конкретного трека). Escape в поле
  переименования отменяет правку и оставляет на странице альбома (раньше событие
  уходило в общий обработчик и уводило «назад»).
- Живая синхронизация между участниками без перезагрузки страницы: Supabase Realtime
  и резервная фоновая сверка каждые 5 секунд, пока вкладка видима.

## Совместное оценивание без перезагрузки

Изменения оценок, подтверждений и удаления подхватываются на открытой странице.
Обновляются средние баллы треков и альбома, вклад каждого участника и статус
подтверждения; главная, профиль артиста и рейтинг также показывают свежие данные.
Бейдж с баллом второго участника, как и раньше, виден **только после подтверждения**;
его неподтверждённый балл участвует в средних значениях на страницах (трека, альбома,
сингла), но **не в рейтингах** — там считаются только подтверждённые оценки.
Оценки синглов синхронизируются так же, как трековые: своя очередь записи на релиз,
защита черновика от старых ответов и подписка на изменения `single_ratings`.

- События Realtime объединяются в последовательные фоновые чтения. Событие,
  пришедшее во время запроса, ставит следующую сверку в очередь, а не теряется.
- Если WebSocket недоступен или событие пропущено, видимая вкладка сверяется с
  базой раз в **5 секунд** (плюс время сетевого запроса). При возвращении на вкладку,
  фокусе окна, восстановлении сети и подключении Realtime сверка запускается сразу.
  В скрытой вкладке и без сети фоновые чтения приостанавливаются; при выходе
  из аккаунта подписка и таймеры очищаются. Зависшее чтение отменяется через 10 секунд.
- Для обновления оценок **не пересоздаются строки треков и поля ввода**: сохраняются
  фокус, незавершённый ввод, положение слайдера и прокрутка. Изменение структуры
  треков откладывается до окончания ввода, переименования или перетаскивания.
- Свои ещё не сохранённые значения защищены от старых ответов сервера.
  Изменение балла, очистка и подтверждение идут через одну очередь записи на трек.
  Ошибка записи действительно показывается как «ошибка», а не «сохранено»;
  черновик остаётся в текущем сеансе и повторяется при возвращении сети/фокуса
  либо следующем редактировании. **При выходе из аккаунта или перезагрузке
  несохранённые черновики не сохраняются.**

Используются существующие таблицы, политики доступа и канал Supabase: новой базы
или миграции для этого изменения не требуется. Даже если публикация Realtime
не настроена, резервная сверка продолжает работать при доступном чтении базы.
В демо-режиме изменения между вкладками одного браузера подхватываются через
события localStorage; данные между разными устройствами в демо не передаются.

## Синглы

Синглы — те же релизы, что и альбомы, но с типом `single` в таблице `albums`:
отдельная оценка на релиз целиком (без треков) и необязательная привязка к альбому.
Наверху главной есть переключатель **«альбомы | синглы»**, выбор запоминается в
браузере. Кнопка справа («рейтинг артистов» / «рейтинг синглов») открывает рейтинг
текущего раздела: **рейтинг синглов** строится только по релизам, оценки которых
подтвердили **все** участники (остальные показаны внизу с подсказкой «оценок пока нет»
или «ждём подтверждения всех оценок»). В подписи строки — год, артист и привязка
(«к альбому «…»»), если она есть; самостоятельному синглу «вне альбома» не пишется.

- **Оценка** одна на релиз: ползунок 0–10 и число, затем подтверждение — как у трека.
  Неподтверждённый балл виден в средних на странице, но не попадает в рейтинг синглов.
  Подпись «подтверждён» и уведомление о подтверждении учитывают обоих участников:
  «сингл в рейтинге» появляется только когда оценки подтвердили все, а до того честно
  пишется «ждём оценку второго участника» или «ждём подтверждения второго участника».
- **Страница сингла** — компактная карточка релиза: обложка, год, артист, балл,
  блок своей оценки и строка привязки к альбому. В конце строки привязки, после
  кнопки «изменить», — кнопка-глаз с тем же отступом, что и соседние кнопки:
  удерживайте её, чтобы увидеть миниатюру обложки основного альбома с подписью
  (название и автор). Миниатюра появляется прямо **справа от кнопки**, у края
  рамки — толстый лавандовый наконечник-указатель; если глаз у правого края
  экрана — карточка разворачивается влево. Отпустили — миниатюра исчезла.
  Работает и с клавиатуры (удержание Enter/Space).
- **Привязка к альбомам** необязательна. При создании сингла или через «изменить»
  перечислите названия через запятую: `MUSIC, MUSIC — демо-издание`. Подсказки
  дополняют последнее название, повторы игнорируются, неизвестное или неоднозначное
  название не сохраняется. Названия с запятой заключайте в двойные кавычки
  (при выборе из подсказок это делается автоматически).
  «Отвязать» или пустое поле убирает все привязки; можно удалить лишь одно название.
  На странице каждого выбранного альбома виден сингл. Если альбомов несколько,
  только на странице сингла серая подчёркнутая кнопка **«показать еще...»**
  стоит сразу после первого альбома и раскрывает остальные ссылки в той же строке:
  через запятую, перед последним альбомом — «и». Первый альбом не повторяется.
  На карточках общего списка и при единственной привязке этой кнопки нет.
  У кнопок одинаковые отступы; раскрытие и сворачивание анимированы, кроме режима
  уменьшенного движения в настройках устройства (сворачивание — заметно шустрее
  открытия, чтобы «скрыть» не ощущалось с задержкой).
  Снятие привязки не удаляет уже добавленные треки и их оценки (метка снимается отдельно).
- **Метка трека**: у каждого трека на странице альбома есть кнопка «отметить как
  сингл». Создаётся карточка сингла (название трека, год и обложка альбома), на треке
  появляется бейдж «сингл». Клик по бейджу открывает сингл сразу, клик по строке трека
  спрашивает «Перейти на страницу сингла?» (да / назад); клик по плашке модалку не
  открывает. Повторная кнопка снимает метку — карточка сингла и его оценки остаются.
  Подпись «Отмечен синглом в N альбомах» считает уникальные альбомы с такими метками
  и учитывает склонение: «в 1 альбоме», «в 11 альбомах», «в 21 альбоме». Без меток скрыта.
- **Сингл — это тоже трек**: когда сингл привязан к альбому, он появляется в конце
  списка треков этого альбома и получает бейдж «сингл». Если трек с таким названием
  уже есть, дубль не создаётся — существующий трек просто помечается. Если артист
  сингла отличается от артиста альбома, название трека записывается как
  «Название & Артист сингла» — совместка со ссылкой на профиль артиста, как у
  обычных фитов (`ft.` / `feat.` / `&`). Название трека при этом строится от
  чистого названия сингла (без фита из его названия), а фит-гость из названия
  сингла на треке своего альбома остаётся фит-ссылкой.
  При зафиксированном количестве треков список не меняется, о чём сообщает уведомление.
- **Обложка**: пока своей нет — берётся у первого выбранного альбома (у самостоятельного сингла — плашка
  с буквой). Свою можно задать или заменить тем же окном, что и у альбома (файл или ссылка).
- **Удаление** — отдельная кнопка на странице сингла, с подтверждением и анимацией.
  Снятие метки и удаление альбома сингл не удаляют: при удалении альбома он остаётся
  с остальными привязками (или без привязок, если удалён последний альбом). Управлять синглами и метками могут оба участника.

Раздел требует обновления базы: `albums.kind`, `albums.parent_album_id`, `albums.parent_album_ids`,
`tracks.single_id`, таблица `single_ratings` с политиками и уникальность
«артист + название» с учётом типа релиза. В SQL Editor выполните `migrate.sql`
(существующая база) или `schema.sql` (новая). Пока миграция не выполнена, раздел
синглов на главной показывает напоминание, а альбомы работают как раньше.
Демо-сид: один самостоятельный сингл и три привязанных. MOJO JOJO размещён на MUSIC
и MUSIC — демо-издание, чтобы проверить несколько привязок.

Для новой возможности **повторно выполните `site/migrate.sql` в Supabase SQL Editor**.
Миграция сохраняет прежние одиночные привязки, проверяет ссылки и при удалении
альбома убирает только его из списка. Обновления используют существующий Realtime
таблицы `albums`.

## Персональное оценивание релиза

При добавлении альбома или сингла админ видит поле **«Кто оценивает релиз»**:
по умолчанию — **все участники**, либо один конкретный зарегистрированный участник
(в том числе сам админ). Выбор окончательный: у существующих релизов назначение
изменить нельзя. Старые релизы остаются совместными.

- У персонального альбома назначенный участник должен подтвердить оценку **каждого
  трека**; у сингла — свою единственную оценку. Тогда релиз получает статус
  «подтверждён» и участвует в рейтинге без оценки второго участника.
- Второй участник видит релиз, баллы, вклад оценивающего и статус подтверждения,
  но поля оценки и подтверждение недоступны. Выбирать целостность/концептуальность
  тоже может только назначенный участник; выбранная целостность видна обоим.
  Прочие права (обложка, треки, удаление, тип релиза) остаются прежними.
  Админ не получает исключение из запрета оценивать чужой персональный релиз.
- У связанных альбома и сингла должны **совпадать оценивающие**: общий ↔ общий,
  либо один и тот же участник. Проверяются все альбомы сингла и метки на треках.
  Несовместимая привязка отклоняется до сохранения. При создании сингла из трека
  назначение наследуется от альбома, в том числе при действии обычного участника.
  Оценки сингла и трека продолжают синхронизироваться.

### Обновление облачной базы

Перед использованием выполните **`site/migrate.sql` целиком в Supabase SQL Editor**.
Для новой базы используйте `site/schema.sql`. Оба файла применяются транзакцией;
повторная миграция сохраняет данные и персональные назначения.

Поле `albums.evaluator_id` ссылается на `profiles.id`; `NULL` означает всех участников.
RLS ограничивает запись оценок, триггеры защищают назначение, целостность и связи.
Удалить профиль назначенного участника нельзя, пока на него ссылаются релизы:
это не должно незаметно превращать персональный релиз в общий.

**Права админа проверяются и на сервере**, через защищённую таблицу `release_admins`.
В миграции добавлен текущий админ из `config.js` (`sportgamergd@gmail.com`). Для другой
инсталляции укажите свой адрес в обоих SQL-файлах перед выполнением. Дальнейшие
изменения списка производятся только владельцем БД в SQL Editor, например:

```sql
insert into public.release_admins(email) values ('admin@example.com') on conflict do nothing;
```

Адрес должен совпадать с адресом аккаунта Supabase Auth и иметь `admin: true` в
`config.js` для отображения выбора в интерфейсе. Изменение только `config.js` или
пользовательских метаданных **не выдаёт серверные полномочия**. Клиент не может
читать или редактировать `release_admins`. В списке выбора отображаются уже созданные
профили. Унаследованный сингл — не новое назначение прав и доступен обоим участникам.

## Как добавить обложку к существующему альбому

1. Войдите и откройте нужный альбом.
2. Под обложкой нажмите **«добавить обложку»** (если её нет) или
   **«изменить обложку»**.
3. Выберите изображение до **10 МБ** или вставьте прямую HTTP(S)-ссылку
   на изображение. Дождитесь предпросмотра.
4. Нажмите **«сохранить»**. До успешного сохранения старая обложка не меняется.
   **«отмена»** или **Escape** закрывают окно без изменений.

Окно и затемнение фона плавно появляются и исчезают. Если в системе включено
уменьшение движения (`prefers-reduced-motion`), анимации практически мгновенные,
а закрытие не задерживается.

Функция доступна обоим участникам, в том числе для альбомов с зафиксированными
треками и типом релиза. Меняется только обложка — не треки, оценки или другие
поля альбома. Карточки и профиль артиста используют обновлённую обложку;
другой участник получает обновление через настроенный Supabase Realtime.

- **Файл:** браузер уменьшает изображение до 900 px по длинной стороне
  (без увеличения маленьких изображений) и сохраняет JPEG. В облачном режиме
  файл попадает в существующий бакет `covers`, а его публичный URL — в
  `albums.cover_url`. Для каждой загрузки создаётся новое имя, чтобы не мешал кэш.
- **Ссылка:** сохраняется сам URL, изображение не копируется в Supabase.
  Лучше использовать HTTPS. Если внешний сайт удалит изображение или запретит
  его показ, обложка перестанет загружаться; загрузка файла надёжнее.
- **Демо:** изображение/ссылка хранится в localStorage этого браузера.
  При нехватке места показывается ошибка, а прежняя обложка остаётся на месте.

Для этой функции **миграция базы не нужна**: используются существующие
`albums.cover_url`, бакет `covers` и политики обновления/загрузки из текущей схемы.
Повторно запускать `schema.sql` или `migrate.sql` ради этой правки не требуется.
При ошибке загрузки проверьте наличие бакета `covers` и права текущего пользователя.
Старые файлы автоматически не удаляются: их URL могут использоваться в других местах.

## Тексты песен с Genius

Кнопка Genius у каждого трека альбома и «пластинка» на странице сингла
открывают текст песни. Текст получает серверный прокси `/api/genius/*`:
в проде это `worker.js` (Cloudflare Worker, указан в `wrangler.jsonc` как
`main`), в локальном превью — тот же эндпоинт в `server.py`. Прокси ищет
песню через официальный API Genius и достаёт текст со страницы genius.com
(браузеру она недоступна из-за CORS), токен Genius хранится на сервере
(можно заменить секретом `wrangler secret put GENIUS_TOKEN`).

- **Что приходит в текст**: только сам текст со страницы (блоки
  `data-lyrics-container`). «Шапку» Genius, которую он с 2025 года кладёт внутрь
  первого блока — счётчик «6 Contributors», переводы, заголовок «<название>
  Lyrics» (`data-exclude-from-selection="true"`, `LyricsHeader__…`), — и подвал
  («Embed») оба прокси вырезают ещё в разметке, а на случай смены вёрстки
  срезают такой префикс и по тексту. Текст начинается сразу с первой строки
  песни, например `[Текст песни «…»]`. Разбор одинаков в `worker.js` и
  `server.py` — это проверяет `tests/genius-extract.spec.ts`; после правок
  разбора повышайте `LYRICS_PARSER_VERSION` в `worker.js`, чтобы суточный кэш
  Cloudflare не отдавал старый вариант.
- **Как ищется**: название трека чистится от фитов и скобок, артист берётся
  до первого разделителя совместки; кандидаты скорятся по нормализованным
  названиям и артисту. Уверенное совпадение открывается сразу и запоминается
  в базе (`tracks.genius_song_id` / `albums.genius_song_id`) — второй участник
  получает готовый текст и жёлтый значок через Realtime. Не уверены — секция
  честно пишет об этом и открывает форму «не тот текст?» со списком
  кандидатов и полем для ссылки на страницу песни (`genius.com/…-9100-lyrics`).
- **Кто меняет выбор**: автопоиск пинит уверенное совпадение от любого
  участника; ручная замена («не тот текст?») и подстановка по ссылке —
  только админ, у остальных подстановка живёт до перезагрузки.
- **Экраны**: альбом — секция под списком треков (антиква 16px, как читалка);
  сингл — «пластинка»: диск с обложкой по центру, при поиске он вращается,
  найденный текст печатается посимвольно с бегущим курсором (в режиме
  уменьшенного движения всё появляется сразу). Ссылки «открыть на Genius»,
  ошибки — с раскрываемыми деталями и кнопкой «скопировать отчёт».
- **Миграция**: требуется **повторно выполнить `site/migrate.sql`** в
  Supabase (добавляются две колонки `genius_song_id` — идемпотентно,
  можно запускать прямо сейчас). Тесты: `tests/genius-lyrics.spec.ts`.

## Поиск обложки онлайн (iTunes и Deezer)

Пока участник добавляет альбом или сингл — а также в окне «добавить/изменить
обложку» на странице релиза — обложку можно не искать вручную: запросы к
**iTunes Search API** и **Deezer API** выполняются автоматически, а найденные
варианты остаются только выбрать.

- **Где работает**: экран добавления (общая для альбомов и синглов) и окно
  обложки существующего релиза. На форме добавления секция «найти обложку
  онлайн» свёрнута в строку-кнопку и сама раскрывается, когда пришли варианты.
- **Как ищется**: заполнили артиста и название — через мгновение (debounce ~0.7 с)
  обе платформы опрашиваются автоматически; запрос можно отредактировать и
  перезапустить кнопкой «искать» или Enter. Поле можно и просто очистить:
  текст не «воскресает» — вписывайте свой вариант; на форме добавления
  следующее изменение артиста/названия снова подставит авто-запрос.
  В окне обложки запрос подставляется из артиста и названия релиза и ищется
  сразу при открытии.
- **Как выбирается**: клик по варианту подсвечивает его лавандовой галочкой и
  подставляет обложку в предпросмотр (на форме — в миниатюру, в окне — в
  предпросмотр и поле ссылки). Установка происходит **штатным сохранением**:
  «добавить альбом/сингл» на форме или «сохранить» в окне — прежняя обложка
  не меняется до успешного сохранения. Ссылка на изображение сохраняется как
  есть (прямая ссылка на CDN платформы — как у опции «ссылка»).
- **Что показывается**: по 6 вариантов от каждой платформы отдельными секциями —
  **Deezer** (альбомы), **Genius** (арты треков), **iTunes** (альбомы магазина US);
  дубликаты убираются. Пока у какой-то платформы нет ключей, под результатами
  видна подсказка о ней.
- **Если платформа не ответила**: у секции появляется честный статус
  («ошибка · network / timeout / parse»), по клику «показать детали» —
  технический отчёт (платформа, запрос, URL, этап, сообщение, время, страница,
  сборка) и кнопка **«скопировать отчёт»** — готовый текст можно прислать
  разработчику для доработки. Остальные платформы продолжают работать;
  файл и ссылка доступны всегда.

**Как устроено.** Запросы уходят прямо из браузера без серверного прокси —
работает на любом домене (Cloudflare, localhost, превью). Транспорт два вида:
**JSONP** (Deezer — у него нет CORS-заголовков; iTunes — надёжнее тем же путём)
и **обычный GET+JSON** (Genius: у его API не проходит CORS-preflight, поэтому
токен передаётся параметром `access_token`, а не заголовком Authorization).
Полная ссылка на изображение проверяется в фоне: если большой размер не
открылся, подставляется уменьшенный, а если не открылось ничего — выбор честно
снимается с подсказкой. Пока идёт сохранение обложки, управление поиском
блокируется. Платформы описаны в реестре `COVER_PROVIDERS` в `app.ts`:
новая платформа — это один объект-адаптер (`id`, `name`, `enabled`,
`transport`, `buildUrl`, `parse`); SoundCloud удалён из резерва как
неподъёмный по регистрации приложений. Тестируется в
`tests/cover-search.spec.ts`: все платформы, обе точки входа (форма и окно),
демо- и облачный режим, ошибки, детали и копирование отчёта.

| `npx playwright install --with-deps chromium` | браузер для тестов (с кэшем) |
| `npx playwright test` | браузерные сценарии, desktop + mobile |

Результат виден в репозитории: вкладка **Actions** → выбранный запуск. Зелёная галочка —
всё хорошо, красный крестик — что-то сломалось: в логе видно, какой шаг и какой тест упал,
а в разделе **Artifacts** того же запуска лежит отчёт `playwright-report` со скриншотами
и трейсами упавших шагов (скачать и открыть `index.html`).

При падении на шаге сверки бандла нужно пересобрать `app.js` (`npm --prefix site run build`)
и закоммитить результат — иначе сайт отдаёт старый код.

Тесты проверяют настольный и мобильный размеры экрана. Проверяются создание
альбома без обложки, загрузка/замена файлом и ссылкой, отмена, неверные и слишком
большие файлы, медленные ответы, нехватка localStorage, ошибки Storage/БД,
защита от повторного сохранения, Realtime и уменьшение движения.
`tests/singles.spec.ts` проверяет переключатель разделов, страницу сингла и её оценку
с подтверждением, рейтинг только по подтверждённым баллам, пометку трека как сингла,
бейдж и модалку перехода, привязку к альбому, удаление сингла и экран добавления.
Там же — страница артиста (сингл с совместкой лежит в «синглах», а не в «при участии»;
в карточке сингла оценки, а не «0 треков», а без оценок подписи нет) и рейтинг
артистов (обложка берётся с лучшей работы, включая синглы, и никогда не остаётся
пустой: свой релиз без картинки заменяется следующим с настоящей обложкой, а при
отсутствии своих релизов — альбомом с фитом).
`tests/track-titles.spec.ts` (демо-режим) проверяет, что при зафиксированном
количестве треков названия всё ещё можно менять — порядок, удаление и форма
добавления остаются заблокированными, а личная фиксация названия по-прежнему
запрещает правку; отмена (Escape) и пустое значение название не меняют.
`tests/mobile.spec.ts` (в демо-режиме) проверяет новый рейтинг альбомов и мобильный
UI: на тач-экране меню «рейтинги» раскрывается вправо и целиком помещается на экране,
ползунок оценки «вооружается» тапом по строке (подсветка, повторный тап и тап вне
списка снимают выделение; числовое поле доступно без активации), а карточки релизов
(альбомы и синглы, на телефоне и на десктопе) выровнены: карточки одного ряда
одинаковой высоты, блок оценки прижат к нижнему краю на одинаковом расстоянии,
счётчик не переносится на вторую строку.
`tests/realtime.spec.ts` дополнительно проверяет два независимых сеанса участников,
фокус клавиатуры и слайдер, сохранение прокрутки и черновиков, задержанные чтения
и записи, подтверждения и удаления, ошибки и переподключение, резервную сверку,
скрытую вкладку, выход/повторный вход и обновление остальных экранов.
`tests/cover-search.spec.ts` проверяет поиск обложек: авто-поиск на форме добавления
и в окне обложки, выдачу всех платформ (Deezer, Genius, iTunes — по 6 вариантов,
в порядке реестра), выбор с подтверждением штатным сохранением (демо и облако),
правку и очистку запроса без «воскрешения» текста, ошибки платформ с деталями
и копированием отчёта, сброс при переоткрытии окна. `tests/genius-lyrics.spec.ts` проверяет тексты Genius: значок трека (серый →
жёлтый), панель с текстом, точный запрос и автозапоминание, форму «не тот
текст», локальную подстановку участника и админскую замену в облаке (PATCH
`genius_song_id`), «пластинку» сингла (вращение, посимвольная печать, пин при
входе) и отчёт об ошибке прокси. `tests/genius-extract.spec.ts` (без браузера)
прогоняет разбор страницы genius.com в `worker.js` и `server.py` на одной
разметке: шапка «6 Contributors … Lyrics» и подвал вырезаны, переносы строк на
месте, оба прокси дают одинаковый текст. Облачные запросы и WebSocket
подменяются тестовыми ответами — **настоящая база Supabase не используется**.

Если когда-нибудь понадобится прогнать то же самое локально, команды такие:
```bash
cd site && npm ci && npm test
```
Это не обязательно: те же проверки выполняет GitHub Actions.

## GitHub, Arena и публикация на Cloudflare

У этого проекта два независимых слоя:

- **Cloudflare** раздаёт HTML, CSS и собранный `app.js` (сам сайт).
- **Supabase** хранит аккаунты, альбомы, треки, оценки и загруженные изображения.
  Подключение задано в `config.js`.

Подключение GitHub к Arena даёт агенту доступ к коду. Это **не означает**, что
каждая правка сразу появляется на рабочем сайте:

1. Агент меняет код в отдельной рабочей ветке, не затрагивая `main`.
   Изменения сохраняются в сессии Arena, но это не то же самое, что отправка в GitHub.
2. Вы проверяете изменения и превью. Тесты и демо-превью не должны менять рабочую базу.
   Обычный локальный запуск с текущим `config.js`, напротив, подключается к тому же
   Supabase, что и опубликованный сайт; для ручных экспериментов используйте демо-режим.
3. После согласования агент может сделать commit, push рабочей ветки и открыть
   **pull request** — предложение внести эти изменения в `main`.
4. После принятия pull request сайт обновится автоматически, **только если**
   Cloudflare связан с репозиторием и настроен деплой из `main`. Если сайт загружался
   вручную, потребуется отдельно опубликовать обновлённые статические файлы.

### Конфигурация Workers Builds

В **корне репозитория** находится `wrangler.jsonc`. Он указывает существующий
Worker **`albumratings`** и папку статических ресурсов **`./site`**. Поэтому
Wrangler знает, что публиковать, даже когда команда запускается из корня,
а не из `site/`. Без этой конфигурации `wrangler versions upload` завершался
ошибкой `Missing entry-point to Worker script or to assets directory`.

Серверный Worker-скрипт не нужен: сайт работает как Workers Static Assets,
а серверные данные обслуживает Supabase. **Не указывайте `site/app.js` как `main`**
в конфигурации Wrangler — это браузерный код, а не серверный обработчик.

Для этой структуры проекта настройки Cloudflare **Settings → Build**:

| Настройка | Значение |
|-----------|----------|
| Root directory | корень репозитория (`/`), **не** `site/` |
| Production branch | `main` |
| Build command | можно оставить пустой: собранный `site/app.js` уже хранится в Git |
| Deploy command (production) | `npx wrangler deploy` |
| Non-production branch deploy command | `npx wrangler versions upload` |

Команда `versions upload` создаёт версию для проверки ветки, не переключая на неё
рабочий сайт. После слияния PR в `main` production-команда `deploy` публикует
обновление. Текущую команду `npx wrangler versions upload` менять для исправления
этой ошибки не требуется: она автоматически прочитает новый `wrangler.jsonc`.
Новый Worker, база или токен для этого не нужны.

### Какие файлы публикуются

`site/.assetsignore` разрешает загрузку **только** `index.html`, `styles.css`,
`app.js`, `config.js` и каталога `covers/`. Исходники TypeScript, SQL, зависимости,
документация и тесты не публикуются как доступные по URL файлы.
При добавлении новых ресурсов для браузера обновляйте этот список разрешений.

`app.js` хранится в Git вместе с исходником `app.ts`: при изменении TypeScript
нужно обновлять оба. Для пересборки из корня репозитория:

```bash
npm --prefix site ci
npm --prefix site run build
```

При желании эти команды можно добавить в **Build command** Cloudflare:
`npm --prefix site ci && npm --prefix site run build`. Корневую папку при этом
оставьте `/`, чтобы Wrangler находил конфигурацию. Для Wrangler 4.129.0 нужен
Node.js 22+.

Проверка конфигурации и состава ресурсов **без загрузки в Cloudflare**, также
из корня репозитория:

```bash
npx wrangler@4.129.0 versions upload --dry-run
npx wrangler@4.129.0 deploy --dry-run
```

Документация Cloudflare: [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)
и [настройка Static Assets / `.assetsignore`](https://developers.cloudflare.com/workers/static-assets/binding/).

## Структура данных (облако)

- `profiles` — участники (id из auth.users, username, initials, avatar_url)
- `albums` — артист, название, год, обложка, tracks_locked, cohesion, album_type,
  `kind` (`album` | `single`), `parent_album_ids` (альбомы сингла)
  и `parent_album_id` (первая привязка, совместимость)
- `tracks` — треки альбома (title, position, locked, feat_artist, `single_id` — метка «сингл»)
- `ratings` — оценка участника на треке (score 0–10, confirmed)
- `single_ratings` — оценка участника на сингле целиком (album_id, profile_id, score 0–10, confirmed)
- `storage.buckets.covers` — обложки и аватары (публичное чтение)

Безопасность на RLS: читают/пишут только вошедшие; свои оценки, ник и аватар
меняет только их владелец; пароли хранит Supabase Auth.
